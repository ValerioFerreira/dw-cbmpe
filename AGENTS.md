# AGENTS.md

## Project Context

CBMPE BI — Command Center. React + Vite SPA, deployed as a static site
(Vercel). No Base44 dependency of any kind remains in this repo.

Since 2026-09-23 there is also a small Node/Express backend (`backend/`):
real auth via SGU, and the admin-editable state (org chart, user-profile
assignments) — see "Backend" below. Since 2026-09-29 it also serves DW/`marts`
data (`/dados/*`: metrics, nominal tables and the DF/Vacinação/Ocorrências panels,
trimmed by the user's profile on the server). Domains still static (JSON generated by
`etl/` scripts) are being migrated one by one; Finanças has been fully on the DW since
2026-10-01 (no JSON, no extractor). The app will leave Vercel for an internal VM: never
keep a JSON fallback just because Vercel can't reach the backend. See `DW_INGESTAO.md`
sections 10–11.

Start with `README.md` for local setup and deploy notes.

## Key Files

- `src/`: frontend application source.
- `src/data/organograma.js`: org-chart/indicator/dashboard/alert data.
  `NODES_PADRAO` is the fallback hierarchy (used when the backend is
  unreachable/unconfigured) — the live hierarchy comes from `GET
  /organograma` (see `src/lib/organogramaClient.js`), editable by an admin
  at `/adm`. `montarOrganograma(nodes)` rebuilds everything else from
  whichever node array is active.
- `src/lib/cbmpe.js`: data-fetching + hierarchy helpers, plus the fetch/
  cache layer for the org chart and user-profile assignments coming from
  the backend (falls back to `src/data/organograma.js`/`accessControl.js`
  local data when the backend is down or unconfigured).
- `src/lib/authClient.js`: SGU login only (CPF + password → `backend/` →
  SGU), since 2026-09-25 — the fixed admin login and the demo logins were
  removed. Admin = SGU user whose matrícula has profile `ADMINISTRADOR` in
  the `app` schema of the `dw` database. Provisional exception: local login
  `AGGD`/`AGGD@GSG` (browser-only, role "admin", no backend token → can view
  everything but never write), kept while the app is on Vercel.
- `src/lib/accessControl.js`: view-level access control (perfil/atribuição/
  unidade model). Still a **visualization-only prototype** — see
  `DW_GOVERNANCA.md`. Profile assignments (`ATRIBUICOES`) are persisted by
  the backend, not `localStorage`, since 2026-09-23.
- `vite.config.js`: plain Vite + `@vitejs/plugin-react`, with `@` aliased to
  `./src`.
- `vercel.json`: SPA rewrite so React Router routes work on direct load.

## Working Notes

- `npm run dev` starts the frontend against local static data — no env vars
  or external services required. It falls back cleanly with `backend/` not
  running (`VITE_AUTH_API_URL` unset/unreachable) — admin write actions
  (org chart edits, user-profile assignments) just won't work.
- Run `npm run lint` and `npm run typecheck` before finishing code changes.
  `backend/` has no lint config of its own — use `node --check <file>` for
  a syntax check there.
- Keep the data shape in `src/data/organograma.js` (UnidadeOrganizacional /
  Indicador / Dashboard / Alerta — see `src/lib/cbmpe.js` for field usage)
  stable if you swap in a real data source, since pages consume it directly.

## Backend (`backend/`, since 2026-09-23)

Small Node/Express service — see its own `.env.example`. Routes:
`/auth` (SGU login + fixed admin login), `/organograma` (org-chart CRUD),
`/atribuicoes` (user-profile-assignment CRUD), `/pessoas` (CPF → matrícula/
OME resolution, admin-only). Write routes require a JWT via
`middlewares/requireAdmin.js`, which accepts only a real SGU-authenticated
user whose own profile (checked live against `backend/data/atribuicoes.json`)
is `ADMINISTRADOR`. State lives in `backend/data/*.json` (no database
of its own) — see `services/*Store.js` for the file-write pattern (atomic
rename, serialized writes) if adding another editable resource.

## Data Warehouse (planejamento em andamento)

Desde 2026-08-07 está em construção o data warehouse real do CBMPE — ETL,
arquitetura de banco (PostgreSQL em servidor interno da corporação),
modelo de tabelas, e conexão com o app e com ferramentas de BI externas
(Power BI/Metabase). **O contrato de dados atual em `src/data/
organograma.js`/`src/lib/cbmpe.js` é só um mock de UI — não é a
especificação do DW real**, e nenhuma visualização atual está congelada.

## LOB Atual/Nova (2026-10-01)

`useCbmpe()` expõe `lob` e `setLob`. A LOB **Nova** usa `NODES_NOVA` (fixa, só visualização;
`/adm` edita só a Atual); a **Atual** usa a árvore do backend com `ajustarLobAtual()` (sem
Estado-Maior, sem DGA, AECI dourada). Dados de unidade renomeada na Nova leem a sigla antiga
(`siglaDeDados()`); unidade `oculto` (DPlaG) soma nas contagens e não aparece; `emConstrucao`
zera os números. Só perfis de acesso total veem o seletor (`podeVerLob`); `LobGuard` volta a
Atual para os demais.
